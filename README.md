# DigitalTwinRecovery

Исследовательский стенд восстановления цифрового двойника по аутентифицированному снимку. Проверяет допуск снимка, целостную замену состояния вместе с метаданными и локальную стоимость операции.

## Метод

`Begin` создаёт `RESYNC_REQUEST` с новым nonce. Источник под блокировкой формирует `CHECKPOINT`: состояние, хеш, версию `(Epoch, Sequence)` и nonce запроса. Полный режим проверяет тип, HMAC, текущий запрос, срок, версию и хеш содержимого. Контекст закрывается до установки, поэтому повторный ответ не применяется.

Версия снимка должна быть не ниже сохранённой `MinimumVersion`: максимума установленной и достоверно известной версии. `ObserveKnownVersion` и `Begin(knownVersion)` принимают доверенные сведения. Равная версия разрешает ремонт состояния; новая эпоха допускает меньший последовательный номер. Во время восстановления обычные дельты заблокированы, после установки возобновляются от новой базы.

Состояния: `Ready`, `AwaitingSnapshot`, `NeedsRecovery`, `CommunicationLoss`, `InstallationFailed`. Сравниваются `HmacOnly`, `HmacVersion` с локальной границей и `Full` с известной границей, nonce и хешем.

## Установка и проверки

Состояние, версия, хеш и нижняя граница объединены в неизменяемый `LocalRecord`. В памяти атомарно заменяется ссылка. Файловое хранилище пишет целую запись во временный файл того же каталога, выполняет `Flush(true)`, заменяет рабочий файл и публикует ссылку. Контрольная сумма выявляет повреждение файловой оболочки.

Самопроверки завершают дочерний процесс перед записью, посередине записи, после Flush до замены и после замены до публикации. После перезапуска проверяется целиком старая либо новая запись. Дополнительно проверяются сохранение границы версии, возобновление дельт и конкурентные читатели.

## Эксперимент и результаты

12 сценариев включают правильный снимок, ремонт равной версии, подмену, чужой запрос, откат, известную границу, смену эпох, закрытый и просроченный запросы, ошибочный хеш источника и обновление при ожидании. `Runs=10000` для каждого из трёх режимов даёт 360 000 прогонов. Учитываются принятие, отказ, сохранение записи, соответствие снимку, приём ниже границы и из другого запроса.

Локальные измерения сравнивают память и файл для состояний 17, 4 113, 65 553 и 1 048 593 байта: три прогрева и 30 повторов на комбинацию, всего 240 измерений. Раздельно измеряются создание снимка и проверка с установкой. Сеть исключена; размер относится к двоичному состоянию, а время зависит от среды. Seed воспроизводит функциональные входы, но не длительность операций.

Серия с seed 20260809 сохранена в `results/reference/`: `report.json` содержит параметры, среду, средние, медианы и процентили; `functional.csv` — функциональные результаты; `summary.csv` — сводку; `samples.csv` — первичные измерения. Новый запуск пишет файлы в `results.local/`.

## Запуск

Требуется .NET 8 SDK, сторонних NuGet-пакетов нет. Из папки проекта:

```powershell
dotnet build -c Release
dotnet run --no-build -c Release -- --self-test
dotnet run --no-build -c Release -- --run --runs 10000 --seed 20260809 --output results.local
python scripts/check_results.py results/reference
```

Для проверки новой серии укажите `results.local`. Без `--run` запускается интерфейс на http://localhost:5082. API: `GET /health`, `GET /api/defaults`, `POST /api/experiment`; дополнительные параметры доступны через API.

SDK-сборка, самопроверки и пересчёт результатов проверены на Windows; подробности — в [отчёте](results/validation/windows-2026-10-10.md). GitHub Actions выполняет сборку, самопроверки и короткий эксперимент.

## Структура и ограничения

`Core.cs` — общие структуры и криптография; `Recovery.cs` — агент, хранилища и эксперимент; `SelfTests.cs` — проверки; `Program.cs` — CLI и API; `Export.cs` — CSV; `wwwroot/` — интерфейс; `scripts/` — воспроизведение и проверка данных.

Источник и ключ доверены, файловое хранилище рассчитано на одного писателя. Остановки процесса не подтверждают устойчивость при отключении питания или злонамеренном откате диска. Снимок соответствует захваченной версии; дальнейшая актуальность требует продолжения синхронизации. Обнаружение рассогласования, устойчивое хранение эпох источника и автоматическая интеграция с [DigitalTwinFreshness](https://github.com/e-shchukin/DigitalTwinFreshness) остаются за пределами эксперимента.
